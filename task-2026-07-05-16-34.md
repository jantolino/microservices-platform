## FASE 3 — Bootstrap manual (usuario, Vault desellado)

- [ ] **m1** Desellar Vault.
- [ ] **m2** Semilla del operador (login con root token dentro de vault-0):

```bash
# 1. Habilitar el auth method kubernetes (compartido por operador y ESO)
vault auth enable kubernetes
vault write auth/kubernetes/config \
  kubernetes_host="https://$KUBERNETES_PORT_443_TCP_ADDR:443"

# 2. Policy de administracion para el operador (minimo privilegio para las CRDs actuales)
vault policy write vault-config-operator - <<'EOF'
# Leer la lista de mounts (deteccion de existencia/drift del SecretEngineMount)
path "sys/mounts"             { capabilities = ["read","list"] }
# Gestionar el SecretEngineMount (secret/ kv-v2)
path "sys/mounts/*"           { capabilities = ["create","read","update","delete","list"] }
# Gestionar la Policy external-secrets
path "sys/policies/acl/*"     { capabilities = ["create","read","update","delete","list"] }
# Gestionar el KubernetesAuthEngineRole external-secrets
path "auth/kubernetes/role/*" { capabilities = ["create","read","update","delete","list"] }
EOF
# NOTA: se quito "sys/auth/*" (no lo usan las CRDs actuales). Reincorporalo solo si
# anades un CRD AuthEngineMount o KubernetesAuthEngineConfig declarativo.

# 3. Role del operador ligado al SA default de secrets-manager
#    (debe coincidir con authentication.serviceAccount.name + namespace de las CRDs)
vault write auth/kubernetes/role/vault-config-operator \
  bound_service_account_names=default \
  bound_service_account_namespaces=secrets-manager \
  policies=vault-config-operator \
  ttl=20s
```

> NOTA: NO se habilita el KV ni se crea el role `external-secrets` a mano; eso lo crean
> las CRDs (`SecretEngineMount`, `Policy`, `KubernetesAuthEngineRole`) vía el operador.
